# ActivityStreams 2.0: профиль архива ЖЖ, версия 1

`data/activitystreams.json` — стандартный экспорт приложения, доступный через **Скачать JSON**. Основа — [ActivityStreams 2.0 Core](https://www.w3.org/TR/activitystreams-core/) и [Activity Vocabulary](https://www.w3.org/TR/activitystreams-vocabulary/), сериализация JSON-LD 1.0, UTF-8. HTTP Content-Type: `application/activity+json`.

Это документ архива, а не сервер ActivityPub. Наличие файла не означает, что сторонняя платформа поддерживает его импорт или особенности ЖЖ.

## Состав

Корень — `Collection`, `items` содержит записи, комментарии и полученные реакции с известными авторами. `totalItems` — число объектов в этой коллекции, включая реакции и комментарии, известные только по метаданным. Это не число записей во всём журнале и не обещание полноты выгрузки.

| Данные | Представление |
|---|---|
| Запись | `Article`, `name`, `content`, `mediaType: text/html`. |
| Комментарий | `Note`, `inReplyTo` — ID родителя, `context` — ID записи. |
| Ответы | `replies: Collection` со ссылками на непосредственно вложенные комментарии, имеющиеся в архиве. |
| Автор | `attributedTo: Person`, имя, ID и URL профиля, когда известны. У анонимного комментария автор не выдумывается. |
| Удалённый комментарий | `Tombstone`, `formerType: Note`, только при явном состоянии D/X. Не вернувшийся при проверке объект удалённым не объявляется. |
| Реакция «нравится» / «не нравится» | `Like` / `Dislike`, `actor`, `object`; только для полученных авторов. |
| Остальные реакции | `type: [Activity, ja:Reaction]`, исходный числовой `ja:reactionType`. Неизвестные типы не подменяются лайком. |
| Изображения в тексте | `attachment: Image`; URL источника, при наличии MIME-тип и локальный путь. |
| Выбранный юзерпик | `icon: Image` на конкретном сообщении, а не текущий аватар профиля автора. |
| Теги | `tag`, объекты с `name`. |
| Дата с известным часовым поясом | `published`, RFC 3339. |
| Дата без часового пояса | `ja:localPublished`; UTC не предполагается. |

ID сообщений имеют вид `urn:livejournal:journal:USERNAME:post:ID` / `…:comment:ID`. Это внутренние ID ЖЖ, не числовая часть веб-URL. Они стабильны между обновлениями архива одного имени журнала, но не обещают независимости от переименования аккаунта. Веб-адрес помещается отдельно в `url`, только если известен. У пользователей с известным числовым ID идентификатор — `urn:livejournal:user:ID`.

Связи выражены через ID, поэтому дерево не требует глубоко вложенного JSON. Ссылка на отсутствующего родителя сохраняется. Если родитель или запись неизвестны даже в метаданных, связи не выдумываются. `replies` описывает полученные ответы, а сведения о полноте находятся в исходном снимке.

`content` содержит очищенное HTML-представление: текст под `lj-cut` раскрыт, ссылки на пользователей и картинки приведены к обычному HTML. Скрипты и обработчики событий исключены. Исходная разметка, включая `lj-cut`, стили и неизвестную кодировку, остаётся в исходном снимке без изменений.

## Полнота и обратное преобразование

`ja:source` — вложенный объект `Document` с `mediaType: application/json`. Его `content` — JSON-строка, содержащая **весь снимок `data/archive.json`**: записи, комментарии, метаданные, пользователей, реакции, юзерпики, карту медиа, историю изменений, область выгрузки и сведения о пропусках. Неизвестные поля также включаются. `ja:sha256` — SHA-256 UTF-8 байтов этой строки.

JSON хранится строкой внутри стандартного `Document` намеренно: произвольный объект с полями `id`, `type` или `@context` JSON-LD-процессор может интерпретировать как связанные данные. Строка сохраняет null, порядок и повторы в массивах, типы значений, большие целые числа и любые имена полей даже после JSON-LD expansion/compaction. Возможности JSON-LD 1.1 не требуются.

Простой способ извлечения:

```python
import json
from pathlib import Path
from ljarchive.activitystreams import source_snapshot

standard = json.loads(Path("journal.json").read_text(encoding="utf-8"))
original = source_snapshot(standard)  # проверяет версию профиля и SHA-256
Path("source.json").write_text(
    json.dumps(original, ensure_ascii=False, indent=2) + "\n", encoding="utf-8"
)
```

Без библиотеки снимок можно извлечь через `json.loads(standard["ja:source"]["content"])`; это не проверяет контрольную сумму. Обратное преобразование означает равенство JSON-значений снимку, а не сохранение пробелов исходного JSON-файла или восстановление рабочей SQLite-базы.

Стандартная проекция предназначена для совместимости. Для полного восстановления данных нужен `ja:source` либо отдельный `data/archive.json`. Программа, игнорирующая расширения, сможет прочитать общие объекты, но может не показать особенности ЖЖ. Полнота данных ограничена тем, что было получено и сохранено архивом; формат не восстанавливает недоступные сервисные данные.

## Расширения

Префикс `ja` определён непосредственно в `@context`:

```json
{
  "@context": [
    "https://www.w3.org/ns/activitystreams",
    {"ja": "https://github.com/vladfedin/journal-archive/blob/main/docs/activitystreams.md#"}
  ]
}
```

| Термин | Значение |
|---|---|
| `ja:profileVersion` | Версия профиля, сейчас 1. |
| `ja:source` | Полный исходный снимок в `Document`. |
| `ja:sha256` | SHA-256 строки `content` исходного снимка. |
| `ja:kind` | `post` или `comment`. |
| `ja:security`, `ja:allowmask` | Исходная видимость записи и маска групп, если получены. |
| `ja:state` | Исходное состояние комментария: A/S/D/X/F или неизвестный код. |
| `ja:metadataOnly` | Есть только метаданные комментария, текст не получен. |
| `ja:contentStatus` | `unavailable` или `unknown-encoding`; отсутствие текста не превращается в пустую строку. |
| `ja:localPublished` | Исходная строка даты, которую нельзя достоверно преобразовать в дату с часовым поясом. |
| `ja:localPath` | Путь к скачанному медиа относительно корня архива, например `media/abc.png`. |
| `ja:userpicSelection`, `ja:userpicKeyword` | Способ определения юзерпика и ключевое слово, когда известно. |
| `ja:reactionCount` | Полученное общее число реакций. Отсутствие поля — неизвестное значение. |
| `ja:reactionCounts` | Полученные счётчики по типам: объекты с `ja:reactionType` и `ja:count`, включая нули. |
| `ja:reactionAuthorsStatus` | `complete`, `partial`, `unavailable` или `not_loaded`. |
| `ja:reactions` | Коллекция ссылок на реакции с известными авторами. |
| `ja:Reaction` | Дополнительный тип активности для реакций ЖЖ, отличных от Like/Dislike. |
| `ja:reactionType` | Исходный числовой тип реакции; новые номера допустимы. |
| `ja:capturedAt` | Время получения реакции, не время её создания. |

Публичная запись имеет адресат `https://www.w3.org/ns/activitystreams#Public`, личная — владельца журнала. Для записей по группам не выдумываются адресаты из маски. У комментариев адресаты не предполагаются по доступности записи: ветка может быть скрыта. Все исходные значения доступа сохраняются в `ja:source`. Поля адресации — метаданные; файл сам по себе не ограничивает чтение.

## Файлы и совместимость

- **Скачать JSON** выдаёт один самодостаточный файл с общими объектами и исходным снимком. Байты медиа в JSON не включаются.
- **Исходный JSON** выдаёт прежний снимок версии 1. Его структура и прежний HTTP-путь `/download/USERNAME.json` сохранены.
- Новый HTTP-путь: `/download/USERNAME.activitystreams.json`.
- ZIP содержит оба JSON, страницы и скачанные медиа. `ja:localPath` отсчитывается от корня этого архива, не от каталога `data`.
- В ZIP также включён `data/activitystreams-context.json` — копия [нормативного контекста W3C](https://www.w3.org/ns/activitystreams.jsonld), полученная 2026-11-16. Независимый JSON-LD-процессор может использовать её через локальный document loader. Само приложение при экспорте и чтении JSON контекст из сети не загружает.
- Старые архивы получают новый файл при открытии в приложении или скачивании ZIP; повторный вход в ЖЖ не нужен. Отдельное скачивание ActivityStreams также преобразует прежний исходный JSON, если рабочей базы уже нет.

CLI без сети и сборки HTML:

```bash
python -m ljarchive json archives/username --format activitystreams --output journal.json
python -m ljarchive json archives/username --format source --output source.json
```

Для обратной совместимости CLI без `--format` сохраняет прежнее поведение (`source`).

## Профиль и переписка в 0.6.0

Социальные связи `friends` / `friendofs` проецируются в `Follow` с направлением `actor → object`; группы доступа и атрибуты связей сохраняются в исходном снимке. Личные сообщения — `Note` с `ja:kind: message`, `ja:security: private`, отправителем `attributedTo` и получателем `to`. Они не адресуются `Public`. `inReplyTo` указывается только при однозначном соответствии исходного `parent` сохранённому `msgid`; сами исходные поля сохраняются независимо от проекции.

Весь `account`, исходные FOAF/Atom документы, настройки и история сообщений входят в `ja:source`. Прямая и обратная конверсия сохраняет их JSON-значения наравне с записями журнала. Полнота истории зависит от выдачи ЖЖ, а не от формата экспорта.
