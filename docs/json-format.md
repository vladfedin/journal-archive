# Формат archive.json, версия 1

`data/archive.json` — полный экспорт исходных данных из SQLite. Кодировка UTF-8, отступ 2 пробела. Можно получить через «Исходный JSON», из ZIP или командой `python -m ljarchive json ПАПКА --output journal.json`. Команда не обращается к ЖЖ и не загружает движок шаблонов.

| Поле | Содержимое |
|---|---|
| `schema_version` | Версия структуры: `1`. |
| `journal` | `username` и числовой `id` журнала (null, если ещё неизвестен). |
| `scope` | `entry_limit` (null — накопительный архив; область последнего обновления — в `last_sync`), `started_at`. |
| `entries` | Исходные записи API ЖЖ. Ключ `itemid`; текст `event`, заголовок `subject`, дата `eventtime`, `props`, `security`, другие исходные поля и `reactions`, если получены. |
| `comments` | Исходные комментарии: `id`, `jitemid` (ссылка на `entries.itemid`), `parentid` (0 — корень), `posterid`, `user` (имя или null), `state`, `body`, `subject`, `date`, `props`, другие исходные поля и `reactions`, если получены. |
| `comment_metadata` | ID, автор и состояние, включая комментарии, чей текст не получен. |
| `users` | Сопоставление ID и имён комментаторов. Авторы реакций находятся в самих реакциях. |
| `versions` | Предыдущие варианты изменённых записей/комментариев: kind, id, saved_at, record. |
| `userpics` | Карты `post` и `comment`, ключ — ID записи или комментария. Поля: исходный `url`, локальный `path`, `keyword` и способ определения `selection`. |
| `media` | Объект «исходный URL → относительный путь к файлу»; null означает, что изображение оставлено ссылкой. |
| `coverage` | Завершённость обхода записей, комментариев, счётчиков реакций и имён авторов. |

В `event`, `body` и `subject` хранится оригинал ЖЖ, включая авторскую разметку HTML. Сгенерированное оформление архива в JSON не включается. Неизвестные кодировки исходных записей могут быть представлены объектом с `base64` и `encoding_unknown`. Отсутствующий `body` означает недоступный текст; пустая строка — полученный пустой текст. Состояния комментариев: A — обычный, S — скрытый, D/X — удалённый, F — замороженный. Неизвестные поля и коды ЖЖ сохраняются.

Начиная с версии 0.5.0 команда «Скачать JSON» выдаёт [ActivityStreams 2.0](activitystreams.md). Описанный здесь формат остаётся доступен отдельно и целиком включён в стандартный экспорт как JSON-документ `ja:source`. Обратное извлечение сохраняет все JSON-значения, включая неизвестные поля, null и порядок массивов.

## Реакции записи или комментария

```json
{
  "count": 2,
  "groups": [1, 0, 1],
  "captured_at": "2026-11-15T22:00:00+00:00",
  "source": "https://likes.services.livejournal.com/get",
  "authors": {
    "status": "complete",
    "captured_at": "2026-11-15T22:00:02+00:00",
    "source": "https://www.livejournal.com/__api/ (likes.get_user_list)",
    "users": [
      {"id": 101, "username": "reader_one", "type": 0, "profile_url": "https://reader-one.livejournal.com/profile/"},
      {"id": 102, "username": "reader_two", "type": 2, "profile_url": "https://reader-two.livejournal.com/profile/"}
    ]
  }
}
```

Это вымышленный пример. Индекс массива `groups` — числовой ID типа реакции, значение — её количество. `type` автора относится к тому же индексу. Сохраняются и неизвестные типы. Текущие типы: 0 — нравится, 1 — пиши ещё, 2 — огонь, 3 — смех, 4 — не нравится, 5 — сочувствие, 6 — возмущение, 7 — OK, 8 — фейспалм, 9 — мне плохо, 10 — фу, 11 — ну такое, 12 — бу, 13 — странные дела, 14 — здесь был кот, 15 — отлично. Иконки и локализованные подписи относятся только к представлению.

`authors.status`: `complete` — получен полный список, совпадающий со счётчиками по типам; `partial` — получена только часть или список не совпал со счётчиками; `unavailable` — сервис не вернул список (описание в `error`). Отсутствующее поле `authors` означает, что список ещё не загружался. Отсутствующее поле `reactions` означает неизвестные счётчики, а не ноль. При подтверждённом `count: 0` список авторов пуст и полон без дополнительного запроса.

ID записи `itemid` и комментария `id` — внутренние ID. Поля `ditemid` и `dtalkid`, когда присутствуют, — ID для URL и веб-API ЖЖ. Их нельзя подменять друг другом. Тип реакции, ID автора и имя сохраняются у каждого объекта; повторение одного автора у разных объектов не удаляется.

Данные можно обрабатывать без шаблонов и браузера. Пароли, сессии и временные токены API не экспортируются. JSON сохраняет тексты и имена, доступные архиву, поэтому уровни доступа из `security` и `state` нужно учитывать при дальнейшем использовании.

Накопительные обновления добавляют `scope.last_sync` (mode, start, end, urls). `source_status: "not_returned"` означает, что сохранённый ранее объект не вернулся при проверке; `body_not_returned` — вернулись метаданные, но не удалось получить свежий текст. Старый текст сохраняется, такие случаи не считаются подтверждённой актуальностью.

Параметры задачи и её прогресс хранятся отдельно в служебной папке `.jobs`; пароля там нет. Поле `request_limit` в отчёте равно `null`, если общий лимит не задан. Версия оформления `format_version` относится к HTML и не меняет `schema_version` JSON.

## Юзерпики

`userpics.post["123"]` и `userpics.comment["456"]` относятся к конкретным сообщениям. Один автор может использовать разные картинки в разных ответах. `url` — исходный адрес, `path` — путь вида `media/…png` относительно корня архива, либо `null`, если файл ещё не скачан. Сам JSON не включает байты картинок; ZIP включает файлы.

`selection`: `selected` — картинка указана в ответе API для данного объекта; `keyword` — выбрана по `props.picture_keyword` из каталога владельца; `default` — запись без ключевого слова, используется основной юзерпик; `none` — сервис подтвердил отсутствие картинки или комментарий анонимный/удалённый; `unknown` — картинку определить не удалось. Если выбранное ключевое слово исчезло, основной юзерпик не подставляется.

Исходные `poster_userpic_url`, `userpic` и `props.picture_keyword` остаются в записях/комментариях, если ЖЖ их вернул. Сохраняется доступная на момент выгрузки картинка; восстановление ранее удалённого или заменённого юзерпика не гарантируется. Разметка `lj-cut` остаётся в исходном `event`; HTML-представление преобразует её в раскрываемые блоки.

## Личные данные (приложение 0.6.0)

Дополнительное поле `account` содержит `sections`, `messages` и `userpic_catalog`. Структура расширена совместимо; существующие поля не переименованы.

- `sections.profile`: разрешённые поля ответа `login`: имя, ID, группы, сообщества и свойства профиля. Cookie, challenge, пароль и токены не сохраняются.
- `sections.foaf`: исходный FOAF/RDF XML (`document`) и плоские поля профиля. Это доступная выдача профиля, не гарантия полноты всех его полей.
- `sections.friends`: ответ `getfriends` с `friends`, `friendofs`, `friendgroups`, масками групп и прочими возвращёнными атрибутами. В исходящих связях могут быть сообщества и RSS-журналы. Это не список всех современных уведомлений/подписок ЖЖ.
- `sections.tags`: исходный ответ `getusertags`.
- `sections.userpics`: Atom XML каталога, URLs, ID, ключевые слова, подписи и даты картинок. Локальные пути находятся в общей карте `media`.
- `sections.settings_display`, `settings_privacy`, `settings_notifications`: доступные checkbox/radio/select-поля страниц настроек, их значения, варианты и выбранные состояния. Текстовые/скрытые поля и секреты формы не экспортируются. Динамические настройки, отсутствующие в HTML, этим способом не покрываются.
- `messages`: исходные записи `getinbox`, ключ `qid`; тип 18 — входящие, 19 — исходящие. Сохраняются `msgid`, `parent`, адресаты, текст, дата и статус прочтения, когда ЖЖ их возвращает. Архив не вызывает `setmessageread` и не отправляет сообщения.

Каждый раздел имеет `source`, `status`, `captured_at`, `checked_at`, `data`, `error`. `captured` означает сохранённый ответ конкретного источника; `source_exhausted` — конец доступной выдачи inbox; `partial` — пропуски; `unavailable` — источник недоступен. Ни один из этих статусов не доказывает наличие всей когда-либо существовавшей переписки. Страницы, курсоры и повторы сохраняются в рабочей базе; одинаковые `qid` не дублируются. Если ограничение `skip ≤ 100` не даёт пройти группу сообщений с одной секундой публикации, раздел остаётся частичным.

История `versions` теперь также содержит `kind: account` (строковый `id` раздела) и `kind: message` (числовой `qid`). Проверка целостности охватывает эти записи. Предыдущие варианты не удаляются при обновлении.

`coverage.discussions` содержит состояние каждого обсуждения: подтверждённые страницы, полученные ID, курсор, `done` и ошибку, если она есть. Отсутствующие поля пагинации не объявляются успехом; исключение — явно пустое обсуждение с `reply_count: 0`, без скрытых комментариев. После трёх проходов незавершённые обсуждения остаются в очереди, остальные данные доступны для чтения.

Источники реализации: [чтение друзей и inbox в протоколе ЖЖ](https://github.com/bradfitz/livejournal/blob/master/cgi-bin/ljprotocol.pl), [генерация FOAF и Atom-каталога юзерпиков](https://github.com/bradfitz/livejournal/blob/master/cgi-bin/ljfeed.pl), [поля настроек](https://github.com/bradfitz/livejournal/blob/master/cgi-bin/LJ/Setting.pm). Доступность конкретных источников проверяется при выгрузке; совместимость с историческим протоколом не гарантирует полноты современной выдачи.

### Удаление комментария

В 0.7.0 явный `state: "D"` (или уже поддерживаемый архивом `X`) означает полученный статус удаления. Отсутствие `body`, отказ в доступе или отсутствие ID в выдаче не доказывают удаление. Неполученный текст обозначается `source_status: "body_not_returned"`; `not_returned` означает отсутствие ранее известного объекта в текущей выдаче.

При подтверждении удаления добавляется `deletion`:

```json
{"observed_at":"2026-11-16T12:00:00+00:00","after_archive":true,"evidence":"getcomments:D"}
```

`observed_at` — первое наблюдение статуса удаления, **не время удаления на ЖЖ**. `after_archive` означает, что до этого наблюдения уже был сохранён текст неудалённого комментария. При первом получении удалённого комментария значение `false`. `evidence` содержит источник явного состояния: `getcomments:D` или `comment_meta:D`. Повторная проверка не сдвигает время первого наблюдения. Ранее полученный `body`, автор, дата, юзерпик и история версий сохраняются. Нетекстовые tombstone-записи не получают искусственный пустой `body` и не входят в ошибки полноты или обязательные цели загрузки реакций.

Статусы `state`, `is_show`, `is_loaded`, `datepostunix` сохраняются отдельно от представления. Для неполученных тел после разворачивания веток допускается до трёх дополнительных окон `comment_meta` на обсуждение за проход. Эти запросы используют общий лимит, задержки и повторы. Если метаданные также не подтверждают удаление, пропуск остаётся пропуском.

### Статистика

`data/statistics.json` — производные данные без оформления, `schema_version: 1`. Функция `ljarchive.statistics.statistics(snapshot)` принимает исходный JSON без базы и сетевых запросов. Поля: `journal`, `years`, `yearly`, `totals`, `coverage`, `people`, `edges`, `revivals`, `returns`.

- `people`: известные авторы, ключ по `posterid` (имя — резервный ключ), число комментариев и разных постов, первая/последняя известная дата, годовые значения и ссылки на примеры. Смена имени при сохранении ID не создаёт нового человека.
- `yearly`: комментарии по **году комментария**, включая анонимные и автора журнала. Дата поста не подставляется вместо неизвестной даты комментария. Год берётся из сохранённой даты, а при её отсутствии — из `datepostunix` в UTC.
- `edges`: направленные прямые ответы между разными известными авторами внутри одной записи, количества по годам, ссылки на примеры. Не включаются ответы самому себе, анонимным авторам, отсутствующим родителям или к самому посту. Ссылки на родителей из другой записи считаются повреждёнными.
- `revivals`: до 30 наибольших пауз от 365 дней между комментариями к записи (либо от публикации до первого известного комментария), с обеими ссылками.
- `returns`: до 30 наибольших перерывов от 365 дней у участников, с обеими ссылками. Это история данного архива, не утверждение о поведении человека вне него.
- `coverage`: полнота обсуждений всех сохранённых записей и область последней выгрузки; завершённое обновление одного периода не подтверждает полноту остальных обсуждений.

Удалённые и скрытые комментарии участвуют в подсчёте по доступным автору и дате; неизвестные авторы, даты и родители учитываются отдельно. Реакции не включаются в временную статистику: дата их фактического добавления неизвестна. JSON со статистикой содержит имена и ссылки на частные обсуждения, как и сам архив.

### Перепосты

Признак `repost: 1` / `"1"` из ответа ЖЖ определяет перепост. Исходные поля, включая `reply_count` и `original_entry_url`, сохраняются без изменений. Обсуждение получает в `coverage.discussions` значения `done: true`, `skipped: "repost"`, `scope: "original-journal"`: это явное исключение чужого обсуждения из области загрузки, а не утверждение о скачивании комментариев оригинала. Ранее полученные данные остаются в исходном JSON, но не показываются как комментарии вашего перепоста и не включаются в статистику общения. В ActivityStreams добавляются `ja:repost` и, если известен, `ja:originalURL`.
