# Формат archive.json, версия 1

`data/archive.json` — полный экспорт исходных данных из SQLite. Кодировка UTF-8, отступ 2 пробела. Можно получить через «Скачать JSON», из ZIP или командой `python -m ljarchive json ПАПКА --output journal.json`. Команда не обращается к ЖЖ и не загружает движок шаблонов.

| Поле | Содержимое |
|---|---|
| `schema_version` | Версия структуры: `1`. |
| `journal` | `username` и числовой `id` журнала (null, если ещё неизвестен). |
| `scope` | `entry_limit` (null — накопительный архив; область последнего обновления — в `last_sync`), `started_at`. |
| `entries` | Исходные записи API ЖЖ. Ключ `itemid`; текст `event`, заголовок `subject`, дата `eventtime`, `props`, `security`, другие исходные поля и `reactions`, если получены. |
| `comments` | Исходные комментарии: `id`, `jitemid` (ссылка на `entries.itemid`), `parentid` (0 — корень), `posterid`, `user` (имя или null), `state`, `body`, `subject`, `date`, `props`, другие исходные поля и `reactions`, если получены. |
| `comment_metadata` | ID, автор и состояние, включая комментарии, чей текст не получен. |
| `users` | Сопоставление ID и имён комментаторов. Авторы реакций находятся в самих реакциях. |
| `versions` | Предыдущие варианты изменённых записей/комментариев: kind, id, saved_at, record. |
| `media` | Объект «исходный URL → относительный путь к файлу»; null означает, что изображение оставлено ссылкой. |
| `coverage` | Завершённость обхода записей, комментариев, счётчиков реакций и имён авторов. |

В `event`, `body` и `subject` хранится оригинал ЖЖ, включая авторскую разметку HTML. Сгенерированное оформление архива в JSON не включается. Неизвестные кодировки исходных записей могут быть представлены объектом с `base64` и `encoding_unknown`. Отсутствующий `body` означает недоступный текст; пустая строка — полученный пустой текст. Состояния комментариев: A — обычный, S — скрытый, D/X — удалённый, F — замороженный. Неизвестные поля и коды ЖЖ сохраняются.

## Реакции записи или комментария

```json
{
  "count": 2,
  "groups": [1, 0, 1],
  "captured_at": "2026-11-15T22:00:00+00:00",
  "source": "https://likes.services.livejournal.com/get",
  "authors": {
    "status": "complete",
    "captured_at": "2026-11-15T22:00:02+00:00",
    "source": "https://www.livejournal.com/__api/ (likes.get_user_list)",
    "users": [
      {"id": 101, "username": "reader_one", "type": 0, "profile_url": "https://reader-one.livejournal.com/profile/"},
      {"id": 102, "username": "reader_two", "type": 2, "profile_url": "https://reader-two.livejournal.com/profile/"}
    ]
  }
}
```

Это вымышленный пример. Индекс массива `groups` — числовой ID типа реакции, значение — её количество. `type` автора относится к тому же индексу. Сохраняются и неизвестные типы. Текущие типы: 0 — нравится, 1 — пиши ещё, 2 — огонь, 3 — смех, 4 — не нравится, 5 — сочувствие, 6 — возмущение, 7 — OK, 8 — фейспалм, 9 — мне плохо, 10 — фу, 11 — ну такое, 12 — бу, 13 — странные дела, 14 — здесь был кот, 15 — отлично. Иконки и локализованные подписи относятся только к представлению.

`authors.status`: `complete` — получен полный список, совпадающий со счётчиками по типам; `partial` — получена только часть или список не совпал со счётчиками; `unavailable` — сервис не вернул список (описание в `error`). Отсутствующее поле `authors` означает, что список ещё не загружался. Отсутствующее поле `reactions` означает неизвестные счётчики, а не ноль. При подтверждённом `count: 0` список авторов пуст и полон без дополнительного запроса.

ID записи `itemid` и комментария `id` — внутренние ID. Поля `ditemid` и `dtalkid`, когда присутствуют, — ID для URL и веб-API ЖЖ. Их нельзя подменять друг другом. Тип реакции, ID автора и имя сохраняются у каждого объекта; повторение одного автора у разных объектов не удаляется.

Данные можно обрабатывать без шаблонов и браузера. Пароли, сессии и временные токены API не экспортируются. JSON сохраняет тексты и имена, доступные архиву, поэтому уровни доступа из `security` и `state` нужно учитывать при дальнейшем использовании.

Накопительные обновления добавляют `scope.last_sync` (mode, start, end, urls). `source_status: "not_returned"` означает, что сохранённый ранее объект не вернулся при проверке; `body_not_returned` — вернулись метаданные, но не удалось получить свежий текст. Старый текст сохраняется, такие случаи не считаются подтверждённой актуальностью.

Параметры задачи и её прогресс хранятся отдельно в служебной папке `.jobs`; пароля там нет. Поле `request_limit` в отчёте равно `null`, если общий лимит не задан. Версия оформления `format_version` относится к HTML и не меняет `schema_version` JSON.
