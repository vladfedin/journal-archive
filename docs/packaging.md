# Сборка и выпуск

Готовые пакеты: [GitHub Releases](https://github.com/vladfedin/journal-archive/releases/latest). Они включают Python, зависимости, сертификаты TLS, шаблоны и статические файлы. Архивы пользователей хранятся отдельно.

## Локальная сборка

На целевой ОС:

```bash
python -m pip install -e ".[test,package]"
python -m pytest -q
python -m build
python packaging/build.py
python packaging/smoke.py
```

`dist/` содержит wheel, sdist и рабочее приложение. `release/` — версионный пакет и SHA-256:

- `JournalArchive-VERSION-windows-x64.exe`
- `JournalArchive-VERSION-macos-arm64.zip`
- `JournalArchive-VERSION-macos-x64.zip`
- `JournalArchive-VERSION-linux-x64.tar.gz`

Нативная проверка запускает приложение вне проекта, без `VIRTUAL_ENV`/`PYTHONPATH`, в папке с кириллицей. Проверяет создание тестового архива, HTML, помощь, CSS/JS, JSON, HTTP и завершение процесса. Также запускает готовый пакет через desktop-launcher поверх имитации сервера 0.3.0, проверяет сохранение очереди и прежней папки, смену версии и повторный запуск без второго сервера. Запросов к ЖЖ нет. PyInstaller требует сборки на целевой системе: [документация](https://pyinstaller.org/en/stable/operating-mode.html).

## GitHub Actions

Матрица: Ubuntu 22.04 x86_64, Windows Server 2022 x64, macOS 15 Apple Silicon и Intel. Сборка запускается на `main`, PR и вручную. Тег `v*` запускает публикацию уже проверенных пакетов этого коммита. Все платформы проходят тесты, сборку и запуск готового пакета. Linux дополнительно проходит браузерные проверки Chromium.

Для выпуска обновите версии в `pyproject.toml` и `ljarchive/__init__.py`, добавьте `docs/releases/VERSION.md`. После успешных проверок `main` отправьте тег `vVERSION`. Публикация берёт артефакты успешных платформ из сборки точного коммита тега и загружает их вместе с SHA-256 в GitHub Release, начиная с Windows. Повторная сборка того же коммита для публикации не нужна. Неудачные или ожидающие платформы пропускаются; их пакеты можно добавить повторным запуском публикации после успешной сборки. Имена, версия и контрольные суммы проверяются до загрузки; уже опубликованный отличающийся файл не перезаписывается.

Пакеты доступны из Releases без входа в GitHub. Автоматическая публикация выполняется на теге `v*` и использует `contents: write`; на `main` и PR пакеты остаются артефактами Actions. Используются [GitHub CLI](https://cli.github.com/manual/gh_release_create) и [токен workflow](https://docs.github.com/en/actions/tutorials/authenticate-with-github_token).

Теги `v*` запускают публикацию готовых артефактов автоматически. Для повторной публикации запустите **Publish ready release packages**. Он находит сборки текущей версии из того же репозитория с точным совпадением коммита тега, принимает только успешно завершившиеся задачи платформ и публикует Windows первым. Артефакты PR, другого коммита, отменённых или неуспешных задач не используются. Существующие идентичные файлы повторно не загружаются. Истёкшие артефакты требуют новой сборки.

## Подпись

Пакеты пока не имеют доверенной подписи Windows и Apple Developer ID/notarization. ОС может потребовать подтверждение запуска; это указано в описании выпуска. Сертификаты не входят в репозиторий. Подпись для широкого распространения можно подключить отдельным этапом перед вычислением SHA-256.

Архивы, SQLite, виртуальное окружение, `.jobs` и локальные данные не включаются в сборку. `MANIFEST.in` исключает пользовательские данные из sdist; PyInstaller получает пакет `ljarchive` и его ресурсы.

## Запуск и смена версии

`desktop.main()` при двойном щелчке вызывает тот же `launch()`, что и `desktop --no-browser --port PORT --output DIR` в нативной проверке. `/api/app` (с локальной сессией) сообщает точную версию, ID экземпляра и рабочую папку; HTTP-заголовки содержат текущую версию пакета. Для 0.3–0.6.1 версия читается из footer, поскольку старый заголовок `Server` мог оставаться `0.4`.

Переход выполняется через `/api/quit`: отмена, завершение рабочего потока с сохранением данных, закрытие порта, запуск новой версии. Ожидание ограничено тремя минутами; принудительного завершения процесса нет. Пока приложение закрывается, новые задачи в нём не принимаются. Смена экземпляра защищена локальной сессией и `expected_instance`.

Короткая файловая блокировка сериализует одновременные старты. `desktop-instance.json` рядом с папкой архивов запоминает порт, ID экземпляра и принятую рабочую папку; паролей и HTTP-cookie в нём нет. При занятом посторонней программой порте приложение выбирает свободный. Последующий запуск проверяет сохранённый ID, прежде чем использовать этот порт. Ошибки записи файлов не маскируются сменой порта.

### Автообновление настольной версии

Приложение запрашивает последний стабильный релиз в `vladfedin/journal-archive`. Для обновления нужны пакет текущей ОС и архитектуры и SHA-256 из метаданных GitHub. Сначала публикуйте пакет под именем, которое формирует `packaging/build.py`. Пока пакет платформы загружается, пользователь может повторить проверку позже.

После загрузки приложение сверяет размер и SHA-256, распаковывает пакет во временном каталоге и запускает его с `--verify-update-version VERSION`. Проверенный экземпляр хранится в пользовательском каталоге приложения внутри `updates`. При следующем запуске исходный EXE или ярлык передаёт новой версии прежние аргументы рабочей папки и порта. Если экземпляр уже запущен, повторное открытие приложения возвращает пользователя в его окно. Для первого перехода с версии без автообновления скачайте пакет вручную.

### Перенос рабочей папки

Кнопка «Переместить» использует локальный авторизованный `POST /api/storage/move` с `{"path":"абсолютный путь"}`. Копирование выполняется в отдельном потоке, прогресс доступен в `GET /api/archives` → `relocation`. Во время переноса экспорт, обновление оформления и создание ZIP/JSON блокируются; HTTP-ссылки архива после переноса остаются теми же.

Перед копированием захватываются блокировки рабочих архивов, SQLite закрывается, каждый файл сверяется SHA-256. Копия собирается в новой временной папке на целевом диске, затем публикуется переименованием. Только после этого рядом с исходной папкой записывается `.ИМЯ-ПАПКИ-location.json` с новым абсолютным путём. Этот небольшой указатель нужен для последующих запусков, в том числе с прежним `--output` и старым реестром desktop launcher. Повторные переносы образуют проверяемую цепочку указателей. Если внешний диск отсутствует, приложение сообщает о недоступности вместо создания пустого архива.

При ошибке до переключения исходная папка не удаляется. После успешного переключения невозможность удалить занятые старые файлы показывается отдельно; новый архив уже доступен. Символические ссылки и непустые папки назначения не объединяются автоматически. Перенос не требует входа в ЖЖ.
