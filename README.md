# Журнал / архив · 0.2

Локальное приложение для сохранения **своего личного Живого Журнала**: записи, в том числе личные и для друзей, комментарии с деревом ответов и скрытые комментарии, которые API ЖЖ отдаёт владельцу.

Результат — одна папка с оглавлением и отдельными компактными HTML-страницами. Поиск работает по полным текстам записей и комментариев, в том числе при открытии `index.html` двойным щелчком, без сервера и интернета. Есть фильтры по годам, меткам и доступу, ссылки на комментарии, сворачивание веток и переходы между записями. Реакции постов и комментариев сохраняются по видам и показываются со счётчиками, включая оглавление.

Страницы архива рассчитаны на чтение с телефона: фильтры сворачиваются, ветки комментариев не выходят за экран. Тёмная тема включается по настройке системы или кнопкой в шапке; выбор запоминается в браузере. Шрифты только системные, поэтому архив по-прежнему ничего не загружает из сети.

## Windows, macOS и готовые пакеты

Интерфейс одинаков на всех системах: локальное приложение запускает сервер на `127.0.0.1` и открывает браузер. Пароль вводится в этой форме. Для завершения фонового процесса есть кнопка «Завершить приложение»; закрытие вкладки само по себе не останавливает выгрузку.

- Windows: запуск исходников через `start.bat` (нужен Python 3.10+); самостоятельный пакет — `LiveJournalArchive-windows-amd64.exe`, со встроенным Python.
- macOS: запуск исходников через `start.command` (нужен Python 3.10+); самостоятельный пакет — `LiveJournalArchive.app` в ZIP, отдельно для Apple Silicon и Intel.
- Linux: `start.sh` или самостоятельный `LiveJournalArchive-linux-x86_64`.

Готовый пакет не требует установки Python. На данный момент локально собран и проверен **Linux x86_64**. Сборки Windows и macOS описаны в `.github/workflows/build.yml`, но их успешный запуск на этих ОС ещё нужно подтвердить выполнением CI. Репозиторий пока локальный; опубликованного GitHub Release нет. Файлы для разных ОС собираются на соответствующих системах, как требует [PyInstaller](https://pyinstaller.org/en/stable/operating-mode.html). Подробности и ограничения подписи приложений: [docs/packaging.md](docs/packaging.md).

Desktop-пакет хранит данные в пользовательской папке: `%LOCALAPPDATA%/LiveJournalArchive/archives` на Windows, `~/Library/Application Support/LiveJournalArchive/archives` на macOS, `~/.local/share/LiveJournalArchive/archives` на Linux (учитывается `XDG_DATA_HOME`). Путь показан в приложении. Исходники и CLI по умолчанию используют `archives/` в текущей папке, либо явно заданный `--output`.

## Создание и обновление архива

В форме доступны четыре режима:

1. **Последние 10 записей** — первоначальная проба, отдельная папка `username-latest-10`.
2. **За период** — даты публикации включительно; можно указать только одну границу. Ограничения на 20 лет нет. Все комментарии выбранных постов читаются за всё время.
3. **По URL** — одна или несколько записей своего журнала, включая URL с `?thread=…`. Обновляется целая запись с обсуждением.
4. **Весь журнал — проверить и обновить** — локальные контрольные суммы, календарь ЖЖ, повторное чтение записей и всех веток комментариев, реакции и авторы.

Для обновления существующего архива нажмите «Обновить архив» в библиотеке и выберите режим. Остальные записи остаются в папке. Старые варианты изменённых записей и комментариев сохраняются в `versions` базы и JSON. Если сервер перестал отдавать запись или комментарий, сохранённый текст остаётся с отметкой `source_status`, без предположения, что он удалён. Контрольные суммы опубликованных файлов находятся в `integrity.json`; они обнаруживают случайные повреждения, а не служат криптографической подписью автора.

Очередь и номер страницы комментариев сохраняются в SQLite. Запуск с тем же архивом и теми же параметрами продолжает незавершённую очередь. После завершённого обновления тот же режим начинает новую проверку. Смена режима или периода начинает другую очередь, сохраняя скачанные данные. Архив содержит накопленные записи: период задаёт объём **этого обновления**, а не фильтр удаления старых данных.

```bash
# Первый архив за 20+ лет, затем повтор той же команды для продолжения:
python -m ljarchive sync username --mode period --from 2005-01-01 --to 2026-11-15 --max-requests 1000
# Только последний период:
python -m ljarchive sync username --mode period --from 2026-11-01 --max-requests 200
# Обсуждение под старой записью, в существующем пробном архиве:
python -m ljarchive sync username --mode urls --url https://username.livejournal.com/12345.html --archive username-latest-10
# Полная проверка с обновлением:
python -m ljarchive sync username --mode full --max-requests 1000
# Локальная проверка без сети:
python -m ljarchive verify archives/username
```

Период не отбирает комментарии по их собственным датам. Чтобы найти новые обсуждения под любыми старыми постами, используйте полную проверку либо явные URL: дата изменения поста не доказывает отсутствия новых комментариев.

## Паузы, отказы и завершение

Запросы идут последовательно. Пауза настраивается, по умолчанию 2 секунды в форме и 3 секунды в команде `sync`; изображения тоже соблюдают темп. Кэш изображений, курсоры страниц и контрольные точки сокращают повторную работу. Это штатные запросы владельца к своим данным; их точный объём показан счётчиком.

- HTTP 429 и 500/502/503/504: до 6 попыток с растущими паузами. Для 429 пауза начинается с минуты; для сетевых сбоев — с 15 секунд. `Retry-After` в секундах или HTTP-дате соблюдается полностью, даже если это несколько часов. Фоновое ожидание можно отменить.
- XML-RPC 402 (ограничение частоты): пауза и повтор с новым challenge. Транспортные обрывы также повторяются в пределах общего бюджета.
- HTTP 401/403, ошибки пароля, CAPTCHA или отсутствие прав: данные сохраняются, автоматические запросы не продолжаются; может потребоваться вход в ЖЖ через браузер и новый запуск.
- После шести неудач работа сохраняется для продолжения. Следующее допустимое время запроса записывается в базу, поэтому перезапуск не сокращает паузу сервера. Пароль и сессия при этом не сохраняются: после перезапуска потребуется войти снова.
- Жёсткий предел HTTP-запросов, по умолчанию **50**, никогда автоматически не сбрасывается. Для большого архива задайте подходящий предел (до 10000) или запускайте продолжение. Повторы, вход, реакции и медиа входят в один счётчик.

Загрузчик рассчитан на завершение через возобновляемые проходы, однако обещать «в любом случае дойдёт до конца» нельзя: сервер может постоянно отказывать, не отдавать скрытые данные, изменить API или удалить тексты. Полнота подтверждается ответами ЖЖ, а известные пропуски остаются в отчёте. Период в 20 лет поддерживается логикой и тестами, но реальный двадцатилетний журнал в этой среде не выгружался.

## Запуск

Нужен **Python 3.10 или новее**. В Linux/macOS из папки проекта:

```bash
./start.sh
```

При первом запуске скрипт создаст `.venv`, установит зависимости и откроет приложение на **http://127.0.0.1:8787**. Для последующих запусков интернет нужен только для выгрузки из ЖЖ.

Ручная установка:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/python -m ljarchive
```

Windows, PowerShell:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m ljarchive
```

1. Введите имя пользователя без `.livejournal.com` и пароль **в локальном приложении**.
2. По умолчанию выбраны **последние 10 постов**, **не более 50 HTTP-запросов** и выгрузка без изображений. Эти настройки можно изменить перед запуском.
3. Нажмите «Создать архив». Держите приложение запущенным; вкладку браузера можно закрыть.
4. Откройте результат и проверьте «Отчёт о полноте». Пробный архив появится в `archives/<имя>-latest-10/`, полный — в `archives/<имя>/`.
5. Для переноса скачайте ZIP, распакуйте его и откройте `index.html`.

Кнопка «Посмотреть пример архива» создаёт **вымышленные** записи без входа в ЖЖ. Это демонстрация интерфейса, не выгрузка вашего журнала.

Чтобы выбрать папку или порт:

```bash
.venv/bin/python -m ljarchive serve --output /путь/к/архивам --port 8788
```

Чтобы запускать без автоматического открытия браузера, добавьте `--no-browser`.

Для независимого фонового запуска в Linux с systemd:

```bash
./start-background.sh
```

Служба продолжает работать после закрытия терминала и перезапускается при сбое. Она доступна на `http://127.0.0.1:8787` до завершения пользовательского сеанса или перезагрузки компьютера; после этого снова выполните команду выше. Проверка состояния: `systemctl --user status livejournal-exporter`. Остановка: `systemctl --user stop livejournal-exporter`.

## Что сохраняется

```text
archives/username/
  index.html                 оглавление, поиск и фильтры
  entries/123.html            запись и её комментарии
  report.html                отчёт о полноте
  export-report.json         тот же отчёт для программ
  assets/                    оформление, JS и поисковый индекс
  media/                     скачанные изображения
  data/entries.json          исходные записи с метаданными
  data/comments.json         комментарии, авторы, родители и состояния
  data/comment-metadata.json метаданные, включая сведения об удалённых
  raw/                       ответы API: JSON, в полном режиме также XML
  archive.sqlite3            база и контрольные точки для продолжения
  archive.lock               блокировка одновременной записи
```

Скрытые комментарии (`state=S`) отображаются с отметкой «Скрытый». Сведения об удалённых комментариях остаются в метаданных, даже когда текста нет. Комментарии к записям, которые не удалось получить, сохраняются на отдельных страницах с объяснением. Очень глубокие ветки не теряются; визуальный отступ ограничен для удобства чтения.

JSON сохраняет исходный HTML и метаданные. В читаемых страницах удаляются скрипты, активные вставки и исходное оформление; содержимое LJ-cut остаётся раскрытым. Внешние видеовставки становятся ссылками. Изображения скачиваются отдельно без передачи сессии ЖЖ другим сайтам; неподдерживаемые или недоступные картинки остаются ссылками. Архив сам не подгружает внешние картинки, шрифты или скрипты при чтении.

ZIP включает читаемые страницы, исходные данные и отчёт. Рабочая SQLite-база в ZIP не входит: для возобновления скачивания сохраняйте исходную папку на компьютере, а для переноса **вместе с прогрессом** скопируйте её целиком.

## Полнота и продолжение

**Пробный режим:** `getevents(selecttype=lastn, howmany=10)` получает последние 10 записей по дате публикации. Затем `getcomments` скачивает страницы комментариев только к этим записям, с `expand_strategy=expand_all`. ID родителей и скрытые состояния сохраняются; для нераскрытых веток выполняется дополнительный запрос в пределах того же бюджета. Если в журнале меньше 10 постов, размер проверяется по календарю. Обход всей истории комментариев для пробы не выполняется. Пробный и полный архивы хранятся в разных папках.

**Накопительные режимы:** календарь ограничивает дни выбранным периодом; записи обновляются без удаления остальных данных. Комментарии читаются по страницам `getcomments` с `expand_all`, включая скрытые, с контрольными точками внутри обсуждения. При обрезанном дне используется `syncitems` с последующей загрузкой отдельных ID. Полный обход истории обновляет и старые обсуждения.

**Жёсткий предел запросов:** по умолчанию 50 за один запуск. Считается каждая попытка HTTP-запроса: challenge, вход, создание сессии, записи, комментарии, реакции, повторы после ошибок, изображения и каждый переход по их редиректам. Счётчик общий для API, сервиса реакций и изображений. Запрос сверх предела не отправляется. Сборка локальных HTML и опрос статуса локальным браузером этот бюджет не расходуют. Счётчик отображается во время работы и сохраняется в отчёте (`requests_used`, `request_limit`, `request_categories`).

При исчерпании предела архив собирается из полученного, пропуски отмечаются в отчёте. Автоматического продолжения с новым бюджетом нет. Каждый **новый запуск пользователем** получает новый лимит; незавершённая выборка 10 постов остаётся зафиксированной, её скачивание продолжается с контрольных точек. Для сценария «10 постов, по одной странице комментариев на пост, без ошибок и изображений» тексты используют 26 запросов; счётчики реакций добавляют по одному запросу на каждые 50 объектов (постов и комментариев); имена авторов — один запрос страницы за токеном и по одному HTTP-запросу на пакет из 10 объектов с ненулевыми реакциями. Оба этапа выполняются перед изображениями. Большие ветки и ошибки увеличивают это число до установленного предела.

**«Тексты выгружены» означает, что проверка выбранного объёма прошла:** в пробном режиме — получены заявленные API страницы комментариев и нет известных неудалённых комментариев без текста; в полном — выполнена сверка с календарём и метаданными. Полнота реакций и наличие всех изображений проверяются отдельно. Отсутствующие тексты, в том числе скрытые, перечисляются в отчёте. Это не гарантия восстановления данных, которых сервер не отдал, и не атомарный снимок: изменения журнала во время скачивания могут потребовать нового запуска.

При обрыве или остановке уже полученные данные сохраняются. Войдите тем же пользователем с той же папкой хранения: завершённые дни будут пропущены, комментарии продолжатся с контрольной точки. Если тексты комментариев были получены не полностью, следующий запуск повторит их обход.

После завершённой пробной выгрузки повторный запуск пробы делает свежую выборку. Накопительные режимы обновляют данные на месте и сохраняют старые варианты изменённых текстов в `versions`. Для независимых резервных копий скопируйте папку архива. Сохранённые изображения используются повторно.

Доступна пересборка HTML без сети, в том числе после аварийного завершения до создания страниц:

```bash
.venv/bin/python -m ljarchive build archives/username
```

## Реакции и форматирование

Счётчики берутся из того же сервиса чтения, которым пользуется интерфейс ЖЖ: `https://likes.services.livejournal.com/get`, `mode: 0`. Параметры содержат ID журнала, записи и комментария. Пароль и сессия в этот сервис счётчиков не передаются. Имена авторов читаются отдельным методом `likes.get_user_list` в `https://www.livejournal.com/__api/`; запросы объединяются в группы по 10 объектов. Для него получается временный токен страницы; при обычной выгрузке используется сессия владельца, при отдельной дозагрузке — доступные без входа данные. Приложение не ставит реакции. Токен и cookie остаются в памяти и не попадают в JSON. Все виды и их количества, ID и имена авторов, ссылки на профили, время получения и источник сохраняются в SQLite и полях `reactions` файлов `entries.json` / `comments.json`.

Если сервис не вернул счётчики или закончился общий лимит, на странице показано «Реакции не загружены», а в отчёте — полученное количество. Нулевой счётчик показывается только при полученном ответе. Нажатие на реакцию раскрывает список имён, с разбивкой по типам. Полнота имён проверяется отдельно: число уникальных авторов каждого типа должно совпадать со счётчиком; пропуски и ошибки отмечаются, доступные имена сохраняются. Реакции — снимок на указанное время, при чтении архива запросов к ЖЖ нет.

Для существующего архива можно отдельно обновить реакции без повторной выгрузки текстов:

```bash
.venv/bin/python -m ljarchive refresh-reactions archives/username-latest-10 --max-requests 50
```

Команда использует отдельный явно заданный лимит и сохраняет его результат в `reaction_refresh`, оставляя счётчик исходной выгрузки. Для старой базы без ID журнала понадобится один запрос открытой страницы записи; если журнал недоступен без входа, ID будет получен при следующей обычной выгрузке с авторизацией.

При пересборке HTML отступы исходного кода не превращаются в пустые строки между HTML-абзацами. Пустые HTML-абзацы убираются, межстрочный интервал и поля уменьшены. Переносы обычного текста и форматирование `pre` / `code` сохраняются. Упоминания `<lj>` превращаются в ссылки независимо от порядка атрибутов.

## Данные независимо от оформления

В разделе «Мои архивы» есть **«Скачать JSON»**. Такой же файл доступен внизу каждой страницы архива. `data/archive.json` — один читаемый UTF-8 JSON с `schema_version: 1`, журналом, записями, комментариями, ID родителей, метаданными, реакциями и их авторами, ссылками на локальные изображения и полнотой загрузки. Он также входит в ZIP. Раздельные `entries.json`, `comments.json` и `comment-metadata.json` сохранены для совместимости.

Экспорт напрямую из SQLite без сети и без загрузки HTML-шаблонов:

```bash
.venv/bin/python -m ljarchive json archives/username-latest-10 --output journal.json
```

Слой данных — `storage.py`, `reactions.py`, `data.py`; внешний вид — `presentation.py`, `render.py`, HTML-шаблоны и CSS. Пересборка страниц не изменяет исходные тексты. В JSON нет CSS, значков реакций, цветов, отступов веток и сгенерированных HTML-страниц. Поля `event`, `body`, `subject` содержат исходный текст ЖЖ, включая авторскую HTML-разметку, если она присутствовала: удаление этой разметки потеряло бы содержание. Документация полей — [docs/json-format.md](docs/json-format.md).

## Ограничения

- Поддерживается личный журнал авторизованного пользователя. Выгрузка сообществ и комментариев пользователя в чужих журналах не реализована.
- Удалённые тексты и комментарии, которые ЖЖ не отдаёт владельцу через API, не восстанавливаются. Отчёт показывает известные пропуски; обхода ограничений доступа нет.
- Вход использует пароль и API ЖЖ. Вход через социальные аккаунты, CAPTCHA и интерактивная двухфакторная авторизация не реализованы. При отказе API приложение покажет ошибку; проверьте обычный вход в ЖЖ.
- Пауза по умолчанию — 2 секунды между запросами. Большие журналы могут скачиваться часами. Временные сетевые ошибки и HTTP 429/5xx повторяются до 6 раз; серверный Retry-After соблюдается полностью. При HTTP 403 запросы этого этапа прекращаются.
- Картинки — JPEG, PNG, GIF, WebP, AVIF до 20 МБ каждая. Приватные изображения, требующие отдельной авторизации, SVG, внешнее видео, опросы и интерактивные вставки не переносятся в работающем виде. Их доступные тексты и ссылки остаются в исходных данных.
- Неопределённые кодировки старых XML-RPC записей сохраняются как base64 с отметкой в отчёте; повреждённый XML останавливает текущую выгрузку, не выдавая её за полную.
- Поисковый индекс содержит полные тексты. Для архивов с сотнями тысяч комментариев браузеру может потребоваться много памяти.

## Учётные данные

Приложение слушает только `127.0.0.1`. Пароль и полученная сессия не записываются в файлы, базу или журналы. В API отправляется challenge-response по HTTPS; MD5 здесь используется только потому, что так устроен протокол ЖЖ. Проверка TLS включена. Ввод пароля происходит в браузере на вашем компьютере; стороннего сервера приложения нет.

Локальные запросы защищены проверками Host, Origin и сессионной cookie. HTML записей очищается, XML разбирается с защитой от внешних сущностей. Одновременная запись в один архив блокируется.

**Сам архив содержит приватные тексты в открытом виде.** Храните его как личные документы и не публикуйте папку целиком без проверки.

## Терминал и проверки

Выгрузка без интерфейса, пароль запрашивается скрытым вводом:

```bash
.venv/bin/python -m ljarchive export username --limit 10 --max-requests 50 --delay 2
# Весь журнал, с явно выбранным большим пределом:
.venv/bin/python -m ljarchive export username --all --max-requests 1000
# Последние 10 постов и изображения; общий предел остаётся 50:
.venv/bin/python -m ljarchive export username --images --max-requests 50
# Пример:
.venv/bin/python -m ljarchive demo
```

Код выхода CLI: `0` — тексты выгружены, `2` — частичная/остановленная выгрузка, `1` — ошибка входа или запуска. При Ctrl+C во время выгрузки приложение завершает сохранение; повторное аварийное завершение всё равно оставляет контрольные точки в базе.

```bash
.venv/bin/python -m pip install -e '.[test]'
.venv/bin/python -m pytest -q
```

Для дополнительной проверки настоящим браузером (сервер должен быть запущен на 8787):

```bash
.venv/bin/python -m pip install playwright
.venv/bin/python -m playwright install chromium
.venv/bin/python tests/browser_smoke.py
```

Проверяются скрытые комментарии и вложенность, разрывы ID, частичные ответы, возобновление, аутентификация challenge-response, XML/HTML, локальный доступ и ZIP. Браузерная проверка проходит поиск по комментариям, фильтры, сворачивание веток, мобильную ширину и чтение через `file://`.

Автоматические протокольные тесты используют тестовые ответы. Дополнительно проверена реальная дозагрузка реакций к существующему архиву из 10 записей и 141 комментария; проверены все 151 счётчик, автономные страницы и отображение в браузере.
